# システム要件定義書 (System Requirements Specification)

本ドキュメントは、ROS/ROS2 自律移動ロボット向け統合ナビゲーションオーサリングツール **「ROS Waypoint Tool」** を、完全ゼロベースで設計・実装・再構築する場合に満たすべき全機能要件、システムアーキテクチャ、不変条件、および非機能要件を定義する公式仕様書です。

---

## 1. システム概要 (System Overview)

### 1.1 目的と背景
自律移動ロボット（ROS/ROS2 Navigation, Nav2 等）の実機運用・経路設計において、環境地図（Occupancy Grid Map）上でのウェイポイント（通過点・目標地点・姿勢）の作成・編集作業は不可欠です。しかし、従来のツールは単なる2次元座標の配置やテキストファイルの直接編集にとどまり、以下のような課題がありました：
1. ロボットの実寸法（フットプリント）や通過コリドー幅を視覚的に確認できない。
2. 障害物回避経路やジグザグ走査経路などのアルゴリズム生成結果と、現場オペレーターによる手動微調整の共存が困難。
3. 仮想壁や進入禁止領域（ベクターROI）、手動の地図修正（ラスター占有格子）を統合的にオーサリングできない。
4. 現場オペレーター向けにUIを簡略化・ホワイトラベル化する仕組みがない。

本システムは、Tauri (Rust) と React / PixiJS (WebGL) を基盤とし、ミリ秒単位で応答する軽量かつ堅牢なデスクトップアプリケーションとして、これらすべての課題を解決する統合オーサリング環境を提供します。

### 1.2 システムの位置づけと対象ユーザー
- **システムの位置づけ**: ROS/ROS2 ナビゲーションエコシステムにおけるオーサリング＆データ生成ツール。
- **対象ユーザー**:
  - **ロボット開発エンジニア**: 高度なスナップ、アンカー相対座標、Nav2フットプリント設定、Handlebarsテンプレートによるカスタム形式出力、Python/WASMプラグイン開発を活用。
  - **現場導入オペレーター / エンドユーザー**: Custom UI（ホワイトラベル＆ステップバイステップ・ワークフロー）を通じて、専門知識なしに安全かつ確実にルート作成・編集を実行。

### 1.3 動作環境および配布形態
- **サポートOS**: Linux (Ubuntu 20.04+, Debian系), Windows 10/11 (x86_64)
- **配布形態**:
  1. **単一実行バイナリ / AppImage / ポータブル版**: インストール不要で即時実行可能。
  2. **インストーラ形式 (deb, msi)**: OSデスクトップ環境への統合。
  3. **Docker 開発環境**: ホストOSを汚染せず X11 転送等で GUI 起動可能なコンテナ環境。

## 2. システムアーキテクチャ & 設計原則 (Architecture & System Invariants)

システム全体は、関心の分離と決定論的動作を保証するため、以下のアーキテクチャ原則に基づいて設計されなければなりません。

### 2.1 4層疎結合連携アーキテクチャ
システムは以下の4層に厳格に分離され、単方向データフローを維持しなければなりません：
1. **UI レイヤー (React / TypeScript)**:
   - ユーザー入力を受け付け、Zustand ストアのアクション呼び出しに変換。
   - 描画ロジックやファイルI/Oの具体実装を持たず、状態のサブスクライブのみに専念。
2. **状態管理層 (Zustand AppStore)**:
   - アプリケーション全体の「単一真実源 (Single Source of Truth)」。
   - 11の機能スライスに分割管理され、不変条件と状態遷移のバリデーションをカプセル化。
3. **描画エンジン (PixiJS WebGL MapCanvas)**:
   - WebGL による高速ハードウェアアクセラレーション描画。
   - ストアの状態を参照して 10層の独立描画レイヤーとして描画し、ポインタ対話をストアアクションへ通知。
4. **ネイティブバックエンド (Tauri / Rust Core)**:
   - ファイルシステムの直接アクセス、ROS マップの画像デコード・解析、Handlebars テンプレートエンジン、マルチレイヤーブレンド並列計算。
   - 外部 Python / WASM プラグインプロセスの標準入出力 (JSON) 経由での起動と非同期通信。

### 2.2 境界隔離原則 (Anti-Corruption Layer / Ingress Pipeline)
外部データ（プロジェクトファイル、LocalStorage、プラグイン通信、外部インポートファイル、IPCメッセージ）は、**必ず各エントリポイントの境界（Migration / Adapter 層）で最新の正規化スキーマへ変換してからドメインコアへ渡さなければなりません。**
- **内部コードでの互換フォールバック禁止**: Zustand スライスや React コンポーネント内で、過去バージョンの互換フォールバック（`data.foo || defaultFoo`）を記述してはならず、常に厳格型（`StrictProjectData`）を前提として動作すること。
- **プロジェクトマイグレーション (`projectMigration.ts`)**: v0 形式の旧データを v1 形式へ自動昇格し、全必須フィールドを完全正規化・補完。
- **ストレージマイグレーション (`storageMigration.ts`)**: LocalStorage に保存されたUI設定のバージョン管理とスキーマ更新時の安全なフォールバック。
- **完全透過永続化**: Rust 側のプロジェクト保存・読み込みは `serde_json::Value` を用いて完全透過に扱い、バックエンドの構造体変更によるデータ消失を防ぐこと。

### 2.3 状態機械モデル (State Machine & Interaction Architecture)
複雑なツールモードや過渡操作の競合を防ぐため、状態機械は以下の5つの直交する独立次元（Orthogonal Axes）の直積集合としてモデル化されなければなりません：

| 直交軸 | 管理領域 | 状態定義と性質 |
|---|---|---|
| **Axis 1: Modal Stack** | `interactionSlice` | 最上位オーバーレイ（LIFOスタック）。モーダル開時はキャンバス操作やグローバルショートカットを完全遮断。 |
| **Axis 2: DOM Text Focus** | ブラウザ DOM | テキスト入力過渡状態。文字・数字キーをDOM要素がローカル専有。ツール切替を遮断。 |
| **Axis 3: Primary Tool Mode** | `interactionSlice` | **8つの完全排他モード** (`AppModeState`)。アプリケーションの主たる操作意図を決定する第一級状態。 |
| **Axis 4: Transient Gesture** | `MapCanvas` | ポインタ押下〜離上（または中断）までの短命過渡状態（ドラッグ、回転、矩形選択等）。アボート登録必須。 |
| **Axis 5: Selection Authority** | `interactionSlice` | **単一権限の排他コンテナ** (`ActiveSelection`)。右ペイン Inspector の表示対象を一意決定。 |

#### 8つのプライマリ対話モード (`AppModeState`)
1. `select`: 通常選択・移動・矩形選択モード
2. `waypoint_add`: ウェイポイント配置・高度スナップ・数値距離入力モード
3. `generator_add`: ジェネレーター配置起点・パラメータ設定モード
4. `annotation_edit`: ベクターROI図形（Point, Line, Rect, Circle等）の描画・変形モード
5. `custom_layer_edit`: ラスターマップのピクセル描画（直線、矩形、円、フリーハンドブラシ）モード
6. `export_region_edit`: マップ切り出し領域の作成・バウンディングボックス変形モード
7. `plugin_interaction`: プラグインからのキャンバス対話入力要求（Interactive Hints）処理モード
8. `element_paste`: 特定属性（X, Y, Z, Yaw）の他ノードへの連続適用モード
9. `measure`: 2点間・オブジェクト間の実寸距離計測モード

#### 4フェーズ同期ライフサイクルパイプライン
すべてのモード遷移は、単一のチョークポイント `transitionToMode` を通過し、以下の4フェーズを決定論的に実行すること：
- **Phase 1: Guard**: 遷移の妥当性検証、同一モードへの冗長遷移判定。
- **Phase 2: OnExit**: キャンバス過渡対話の安全なアボート（初期値ロールバック）、同期リスナー通知。
- **Phase 3: State Mutation**: 新モードへの状態更新、非互換な選択状態の自動解除。
- **Phase 4: OnEnter**: 新モードの初期化、同期リスナー通知。

#### 階層型エスケープ・パイプライン (Tier 1〜Tier 7)
`Esc` キー押下時は、以下の順序律に従って単一ステップずつ段階的にキャンセル・解除を実行すること：
- **Tier 1 (最前面モーダル)**: 最上位モーダルの閉塞（スタック POP）。
- **Tier 2 (入力フォーカス)**: DOM テキストフォーカスの解除 (`blur()`)。
- **Tier 3 (過渡ジェスチャー)**: ドラッグ・変形操作の中断と初期座標への原子的ロールバック。
- **Tier 4 (精密スナップ入力)**: スナップ数値入力バッファのクリア。
- **Tier 5 (選択解除)**: `ActiveSelection` の解除（非選択状態へ移行）。
- **Tier 6 (モード復帰)**: 特殊編集モードから `select` モードへの安全な復帰。
- **Tier 7 (アイドル)**: 変更なし（基底状態）。

### 2.4 システム不変条件 (System Invariants)
1. **コンテナ受入不変条件 (Container Acceptance Invariant)**:
   - ツリー構造において子ノード（`children_ids`）を保持できるのは `manual_group` および `group` のみとする。
   - `generator`（自動生成）および `manual`（単一ノード）への子ノードドラッグ＆ドロップや挿入はドメイン境界で厳格に拒絶（Reject）すること。自動生成ノードを手動編集したい場合は明示的な「グループ展開 (Explode)」を必須とする。
2. **経路走査の正準 DFS 規約 (Canonical Traversal Standard)**:
   - ウェイポイントの順序（番号順）を扱うすべての機能（パス描画、ルーター、エクスポート、経路長計算等）は、共通関数 `getFlattenedWaypointIds` による深さ優先探索（DFS）を単一真実源とすること。
3. **マップ原点の 2D 剛体変換規約 (Rigid 2D Map Origin Transform)**:
   - ROS マップ原点 `origin: [x, y, yaw]` に対し、世界座標 $(x_w, y_w)$ とピクセル座標 $(c, r)$ の相互変換は、必ず $Yaw$ 回転行列 $R(\theta)$ を含む 2D 剛体変換式を一貫適用すること。
4. **ツリー変形時の挿入境界射影規約 (Adjacent Boundary Projection Standard)**:
   - ノード削除、グループ化、グループ解除、移動などのツリー変形時、新規追加先を示す `insertionTarget` は共通写像関数 `mapInsertionTarget` を介して直前ノード基準で安全に追従・更新すること。

## 3. 機能要件 (Functional Requirements)

### 3.1 マップ管理・描画要件 (Map Management & Visualization)
- **ROS 標準マップ読み込み**: ROS / ROS2 標準の 2D Occupancy Grid Map ファイル（YAML メタデータ + PGM/PNG/BMP 等の画像ファイル）を読み込めること。
- **複数マップレイヤー管理**:
  - 複数のマップを独立したレイヤー（`MapLayer`）として保持・管理できること。
  - レイヤーごとに表示/非表示のトグル、不透明度（0〜100%）のスライダー調整、重ね合わせ順序（z-index）のドラッグ＆ドロップ並び替えができること。
  - アクティブマップの設定およびアクティブマップ解像度の自動継承ができること。
- **PixiJS 10層描画スタック順序**:
  キャンバス内の WebGL コンテナは、背面から前面に向かって以下の厳格な重なり順およびイベント優先度で描画されなければならない：
  1. `MapLayerSprite` (Base Map): 背景 ROS マップ画像
  2. `Custom Layers` (Raster / Manual Vector): 手動描画およびプラグイン生成カスタムレイヤー
  3. `GridLayer`: ワールドグリッド線（1mメッシュ等）
  4. `PathLayer`: ウェイポイント間パス補間線・実寸コリドー帯
  5. `FootprintLayer`: ロボット形状フットプリント表示
  6. `AnnotationLayer`: アノテーション図形（Point, Line, Rect, Circle等）
  7. `WaypointLayer`: ウェイポイント矢印マーカー、ラベル、回転ハンドル
  8. `PluginLayer`: プラグイン自動生成プレビューおよび Interaction Hints 視覚補助
  9. `ExportRegionLayer`: マップ切り出しエクスポート枠
  10. `SnappingGuideLayer`: 直交スナップガイド線および数値入力 HUD（最前面）
- **GPU GLSL シェーダーによる3色占有ハイライト**:
  - PixiJS カスタムシェーダーフィルター（`OccupancyHighlightFilter`）により、マップ画像を占有格子 3 領域（障害物: 赤, 自由空間: 緑, 未知領域: 紫）にリアルタイム色分け表示できること。
  - 設定画面から障害物閾値（`defaultOccupiedThresh`）、自由空間閾値（`defaultFreeThresh`）、ネゲート反転（`defaultNegate`）を動的に調整可能であること。
- **マップフィット & ビューポート制御**:
  - マウスドラッグによるキャンバスのパン（平行移動）、マウスホイールによるスムーズなズームイン/アウト。
  - `View > Fit to Map` メニュー、ステータスバーの Fit ボタン、またはホイール中ボタンのダブルクリックにより、描画中のマップ全体がビューポートへ即座に最適化表示されること。

### 3.2 Waypoint 作成・編集・階層管理要件 (Waypoint Editing & Hierarchy)
- **基本作成と姿勢制御**:
  - キャンバス上のクリックで任意位置に Waypoint を配置できること。
  - データモデルとして位置 $(x, y, z)$ および姿勢クォータニオン $(qx, qy, qz, qw)$ を保持すること。
  - 矢印マーカーの先端にある回転ハンドルをドラッグすることで、キャンバス上で直感的に姿勢（Yaw 角）を編集でき、Yaw 角とクォータニオンが自動相互変換されること。
- **高度な直交スナップ & 連続配置**:
  - `waypoint_add` モード時、既存ポイント近傍で X/Y 直交軸へ自動スナップ補助線を描画すること。
  - **HUD 数値距離入力**: テンキーまたは数字キーで数値を直接入力（例: `1.5`）して `Enter` を押すことで、基準ポイントから指定距離の位置に正確にノードを追加できること。
  - **軸方向ロック**: 矢印キー（`↑`, `↓`, `←`, `→`）により、基準ポイントからの配置方向を拘束できること。
  - **基準点切替**: `Tab` / `Shift+Tab` キーにより、スナップの基準となるノードを直感的に巡回切り替えできること。
- **階層ツリー構造 (`WaypointTree`)**:
  - ノード種別として単一ノード（`manual`）、自動生成グループ（`generator`）、手動グループ（`manual_group`）、汎用グループ（`group`）をサポートすること。
  - ツリー上でのドラッグ＆ドロップによる並び替えに対応すること。不連続な複数選択ノードの一括ドラッグに対応し、ドロップ先で自動的に連続化配置されること。ドラッグ中は `DragOverlay` によるスタックカード表現を行うこと。
  - **挿入位置インジケーター（挿入バー）**: 次に新規追加されるノードの挿入位置（親IDおよびインデックス）をツリー上に青いラインで視覚表示し、ツリー行のクリックで挿入先を変更できること。
- **アンカー設定 & 相対座標編集**:
  - 任意のノードを「アンカー（基準点）」として指定でき、インスペクター上でアンカー基準の相対位置 $(dx, dy, dz)$ および相対角度 $(dYaw)$ を確認・編集できること。
- **属性の連続コピー (`element_paste` / `ElementCopyOverlay`)**:
  - インスペクター内の Transform 各フィールド（X, Y, Z, Yaw）のラベルを右クリックし、その値をコピーした状態でキャンバス上のノードを連続クリックすることで、同値を瞬時に適用できること。
- **右クリックコンテキストメニュー**:
  - キャンバス上およびツリー上のノードに対し、単一/複数選択項目の一括複製、一括削除、アンカー設定、内部プロパティ表示、ジェネレーター展開（Explode）を実行できること。
- **キャンバス上プロパティ描画**:
  - `View > Show Properties` トグルにより、キャンバス上のノード近傍に座標や Yaw 角、カスタムオプション値を直接テキスト描画できること。

### 3.3 アノテーション要件 (Vector ROI / Metadata)
- **5種のベクター幾何図形**:
  - `Point`: 点（位置 $x, y$）
  - `OrientedPoint`: 向き付き点（位置 $x, y$、角度 $yaw$）
  - `Line`: 線分（始点 $x1, y1$、終点 $x2, y2$、実寸長さ表示トグル `showLength`）
  - `Rect`: 矩形（中心 $cx, cy$、幅 $width$、高さ $height$、回転角 $angle$）
  - `Circle`: 円形（中心 $cx, cy$、半径 $radius$）
- **アノテーションの編集とインタラクション**:
  - `annotation_edit` モードにおいて、キャンバス上でドラッグによる新規ラバーバンド描画が可能であること。
  - 選択時、頂点操作ハンドル、リサイズハンドル、回転ハンドルを描画し、キャンバス上で直感的に幾何変形できること。
  - キャンバス上部にフローティングアクションバナー（`AnnotationEditOverlay`）を表示し、サブツールの切り替えや色変更、完了操作を提供すること。
- **階層管理とグループ化 (`AnnotationTree`)**:
  - アノテーション一覧のツリー表示、並び替え、可視性トグル、名前編集、カラー設定、削除、複製をサポートすること。
  - プラグイン生成によるグループ（`generator`）および手動グループ（`manual_group`）をサポートすること。
- **プラグイン入力参照**:
  - プラグインの入力（`type: "annotation"`）として、特定の幾何タイプ（`object_type: "line"` 等）または任意のアノテーションを指定してアルゴリズムへ渡せること。

### 3.4 カスタムレイヤー要件 (Raster Custom Layers)
- **手動ベクター描画レイヤー (`manual`)**:
  - 直線（`line`）、矩形（`rect`）、円形（`circle`）、フリーハンドブラシ（`freehand`）を用いて、0〜255 の占有値（0: 障害物/黒、255: 自由空間/白）を持つオブジェクトを描画・編集できること。
  - 既存図形のリサイズ・回転・端点移動ハンドルによる編集をサポートすること。
- **プラグイン生成レイヤー (`plugin`)**:
  - 外部プラグインが出力した Base64 形式の Occupancy Grid 画像をカスタムレイヤーとして登録・表示できること。
- **レイヤー合成とブレンドモード**:
  - レイヤーごとに不透明度（0〜100%）、重ね合わせ順序、および3つの描画ブレンドモードを設定できること：
    - `overwrite`: 上層レイヤーの値で完全上書き。
    - `merge_obstacles`: 障害物ピクセル（低値）を優先合成。
    - `merge_free`: 自由空間ピクセル（高値）を優先合成。
- **Rust 高速マルチレイヤーブレンドプレビュー (`blend_map_preview`)**:
  - 背景マップおよび全カスタムレイヤーの合成結果を、Rust バックエンドの高速並列処理によりリアルタイムに合成・プレビュー表示できること。

### 3.5 ロボットフットプリント & パスルーティング要件 (Footprint & Paths)
- **ロボットフットプリント定義 (`RobotFootprint`)**:
  - 以下の3種類のフットプリント形状をサポートすること：
    - `circular`: 半径 (m)
    - `rectangular`: 前後長 $length$、左右幅 $width$、中心オフセット $offset_x, offset_y$ (m)
    - `polygon`: 局所座標系における頂点点群 $[[x, y], ...]$ (m)
  - 設定画面（`RobotFootprintTab`）においてリアルタイム SVG プレビューおよび ROS Nav2 形式テキストの双方向編集ができること。
- **キャンバス上でのフットプリント可視化**:
  - 選択中のノード、および表示トグル有効時の全ノードに対して、ノードの姿勢（Yaw 角）に合わせた実寸フットプリント外枠・半透明塗りつぶし・進行方向インジケーターを描画できること。
- **パスルーティングと自動再計算**:
  - ウェイポイント間を接続する経路として、単純直線補間に加え、`path_calculator` プラグイン（組み込み Dijkstra 回避パス等）による自動障害物回避経路の算出をサポートすること。
  - ノードの追加・移動・削除時に自動的にパスを再計算する「Auto Recalculate」トグルを提供すること。
- **実寸コリドー帯の描画 (`PathLayer`)**:
  - パスラインに対し、色・透過度・線幅（実寸メートル幅）のカスタマイズ、およびロボットフットプリント幅との自動同期をサポートすること。

### 3.6 実寸計測ツール要件 (Measurement Tool)
- `measure` モード（`M` キー）において、キャンバス上の2点クリック、または既存ノード/アノテーション頂点間をクリックすることで、ワールド座標系での実寸直線距離 (m) および各軸成分 ($dx, dy$) をリアルタイム計測できること。
- 計測結果をキャンバス上に HUD 距離バッジとして表示し、ワンクリックで寸法線アノテーション（`LineAnnotation`）としてプロジェクトに保存できること。

### 3.7 条件付き書式要件 (Conditional Styles)
- **動的スタイルオーバーライド**:
  - プロジェクト設定で定義された条件ルールに基づき、キャンバス上の描画スタイルを動的に変更できること。
  - 対象要素 (`TargetElementType`): `waypoint`, `path`, `footprint`, `annotation`
- **ネスト可能な条件グループ**:
  - AND / OR 論理演算子による多階層グループ化。
  - 比較演算子: `equals`, `not_equals`, `greater_than`, `greater_than_or_equal`, `less_than`, `less_than_or_equal`, `between`, `contains`, `in`, `is_empty`, `is_not_empty`
  - 評価対象プロパティ: ノードの属性（`options.speed`, `name`, `type`, `index` 等）
- **オーバーライド可能スタイル**:
  - ウェイポイント: 色、塗りつぶし色、スケール、不透明度、形状（`default`, `circle`, `square`, `diamond`, `star`）、ラベル表示。
  - パス: 色、線幅、オプション値直接参照（`widthFromOption`）、不透明度、破線パターン（`solid`, `dashed`, `dotted`）。
  - フットプリント: 表示モード（強制表示/非表示）、寸法モード（オプション参照、カスタム値）、線色、塗りつぶし色。
  - アノテーション: 枠線色、塗りつぶし色、線幅、不透明度、可視性。
- **ルール評価とインポート/エクスポート**:
  - ルール一覧のドラッグ並び替え（優先度制御）、マッチ時評価停止フラグ（`stopIfMatched`）。
  - ルール設定の JSON エクスポートおよびインポート機能。

### 3.8 カスタム属性要件 (Option Schema)
- **動的スキーマ定義**:
  - ウェイポイントごとに任意の属性（例: 目標速度、停止時間、動作モード）を定義できること。
  - サポートする型: `string`, `float`, `integer`, `boolean`, `list`（選択肢 enum 定義）。
- **フォーム動的生成とプロジェクト永続化**:
  - 定義されたスキーマは `.wptroj` に保存され、右ペイン Inspector の「Options」セクションに入力フォーム（テキスト入力、数値スライダー、トグルスイッチ、プルダウン等）を自動生成すること。

### 3.9 プラグイン & パイプライン要件 (Plugins & Pipelines)
- **プロセス間通信**:
  - OS の標準入出力 (`stdin` / `stdout`) を介した JSON 形式通信。
- **プラグイン種別**:
  - `python`: 外部 Python スクリプト実行。
  - `wasm`: WebAssembly バイナリ実行。
  - `pipeline`: 複数プラグインを組み合わせたレシピ実行。
- **統合ジェネレーター (`PluginGenerator` & `PluginResult`)**:
  - 1回のプラグイン実行で、ウェイポイント配列、カスタムレイヤー画像、アノテーショングループ、および内部計算メタデータ（`plugin_data`）を同時に複合出力できること。
- **入力定義体系 (`inputs`)**:
  - `point`: 単一座標・Yaw
  - `points`: 複数点群（追加、移動、削除）
  - `rectangle`: 矩形領域
  - `waypoint`: 既存ウェイポイント参照（ID, 座標, オプション）
  - `annotation`: 既存アノテーション参照
  - `custom_layer`: 既存カスタムレイヤー参照
  - プリミティブ値: `float`, `integer`, `string`, `boolean`
- **コンテキスト要求 (`needs`)**:
  - プラグイン宣言に応じ、`selected_points`、`occupancy_grid`、`occupancy_grid_in_region`、`robot_footprint` を入力コンテキストに自動注入すること。
- **インタラクションヒント (`interaction_hints`)**:
  - プラグインがキャンバス上に補助図形を描画するためのヒント情報（走査方向矢印、開始コーナー点等）を定義できること。
- **Diff & Stash 競合管理機構**:
  - 自動生成ノード（`generator`）生成時の基準データ（`baseline_waypoints`）を保持すること。
  - 生成後にユーザーが手動で個別ノードの座標やオプションを変更した場合、その差分を `WaypointDiffItem` として追跡すること。
  - プラグインパラメータ変更に伴う再生成（Regenerate）時、手動変更が存在する場合は競合解決ダイアログ（`GeneratorRegenerateConflictModal`）を表示し、「手動編集を保持して再生成（Stash適用）」「手動編集を破棄して完全上書き」「キャンセル」を選択できること。
- **ジェネレーター展開 (`Explode`)**:
  - 自動生成グループを不可逆的に「手動グループ（`manual_group`）」へ展開し、各ノードを完全に独立した手動ノードとして自由編集できるようにすること。
- **パイプラインシステム (`PipelineRecipeDef`)**:
  - 複数プラグインの実行ステップをレシピとして定義し、前段ステップの出力（カスタムレイヤー、アノテーション等）を後段ステップの入力へデータバインディングできること。
  - パイプライン実行時、必要な手動入力を集約したセットアップ画面（`PipelineSetupView`）を自動提供すること。
- **Python 仮想環境管理 (venv) & 開発支援**:
  - 設定画面からプラグイン用の Python 仮想環境を作成（`create_virtualenv`）、必須パッケージの依存確認（`check_python_packages`）、および pip インストール（`install_pip_packages`）を GUI から実行できること。
  - プラグイン新規作成ウィザード（`scaffold_plugin`）、SDK バージョン確認・更新機能を提供すること。

### 3.10 入出力 & エクスポートプロファイル要件 (I/O & Export Profiles)
- **完全内包プロジェクトファイル (`.wptroj`)**:
  - マップ画像（Base64）、全ノード階層、アノテーション、カスタムレイヤー、フットプリント、オプションスキーマ、エクスポートテンプレート、UI状態等をすべて単一の JSON ファイルに内包保存・復元できること。
- **Handlebars 自由テンプレート出力**:
  - 組み込みの ROS 標準 `waypoints.yaml` に加え、ユーザー定義の Handlebars テンプレートにより任意の形式（JSON, CSV, XML, カスタムYAML等）で出力できること。テンプレートごとに出力ファイル名サフィックス（例: `_nav.yaml`）を設定できること。
- **柔軟なインポート & マッピング自動推論**:
  - 外部ファイル（CSV, JSON, YAML等）のインポート時、フィールドマッピング設定（`ImportFieldMapping`）を介してノードへ読み込めること。
  - エクスポートテンプレートの内容を解析し、インポートマッピングを自動推論する機能（`infer_import_mapping`）を提供すること。
- **一括エクスポートプロファイル (`ExportProfile`)**:
  - 複数の出力ターゲット（Handlebars テンプレート、デフォルト YAML、切り出しマップ領域等）を1つのプロファイルに集約し、相対出力パスパターン（例: `routes/{{name}}.yaml`, `maps/{{region_name}}.png`）を定義できること。
  - ワンクリックで全成果物を一括生成でき、既存ファイルとの衝突を事前検知（`check_export_conflicts`）して「上書き（`overwrite`）」または「自動バックアップ生成（`backup_file`）」を選択できること。
- **マップ切り出しエクスポート**:
  - キャンバス上で作成したエクスポート領域（`ExportRegion`）の切り出し画像を保存できること。
  - ラスタライズ解像度は「1. アクティブマップ解像度、2. ユーザー任意指定、3. フォールバック 0.05m」の優先解決ポリシーで決定されること。

### 3.11 Custom UI & ワークフロー要件 (White-labeling & Workflows)
- **外部設定ファイルによる完全オーバーライド**:
  - アプリ実行ディレクトリまたはユーザー設定ディレクトリに配置された `custom-ui.config.json`（または開発用 `custom-ui.dev.json`、サンプル `custom-ui.sample.json`）を読み込み、コアロジックを改変せずにツール全体を専用ツール化できること。
- **ブランディング & 動的テーマ**:
  - アプリ名、ウィンドウタイトル、アイコン、ロゴ画像、About 画面の情報を上書きできること。
  - CSS 変数注入（`ThemeInjector`）により、コーポレートカラーやパネル背景色、文字色を自由に変更できること。
- **レイアウト制限 & フィルタリング**:
  - 左右パネルの所属タブ、デフォルト幅、分割/タブ表示モード、ツールバー表示ツール、メニュー項目の表示/非表示を制御できること。
- **ワークフローガイド (`WorkflowPanel`)**:
  - 初心者や現場オペレーター向けに、ステップバイステップの作業手順（1. マップ読み込み → 2. ロボットサイズ確認 → 3. ルート作成 → 4. 保存）を案内するパネルを提供できること。
  - 各ステップに連動したライフサイクルアクション（モード遷移、マップフィット等）、簡易パラメータコントロール（スライダー、トグル等）、ワンクリック実行ボタンを配置できること。
- **カスタム Web パネル (`CustomHtmlPanel`)**:
  - ユーザー自作の外部 HTML ファイルや Web ダッシュボードをタブ内に iframe 埋め込み表示し、PostMessage 経由でアプリ側アクションを呼び出せること。
- **標準モードとのシームレスな切替**:
  - Custom UI モード適用中であっても、TopMenu の Help から即座にフル機能の標準モードと相互に行き来できること。

### 3.12 UI/UX & インタラクション要件 (Usability & Safety)
- **カスタムタイトルバー**:
  - OS ネイティブのタイトルバーを非表示にし、TopMenu、プロジェクト名表示、未保存バッジ、ウィンドウ最小化・最大化・閉じるボタンを統合した独自のモダン UI を提供すること。
- **柔軟な左右ドッキングパネル (`PanelContainer`)**:
  - 左右のパネルを「タブ切り替え」または「上下分割表示」に切り替えられること。
  - タブヘッダーの右クリックにより、タブを反対側のパネルへ移動（左右ドッキング）したり、ドラッグ＆ドロップでタブの並び替えができること。
  - パネル境界のドラッグによる自由なリサイズ、および `View > Reset Window Layout` によるワンクリック初期化をサポートすること。
- **高機能ステータスバー (`StatusBar`)**:
  - 画面最下部に常駐し、現在のモードバッジ、Escキー遷移先ボタン、バックグラウンドタスク進捗、カーソル世界座標 $(X, Y)$・極座標・ローカル座標、挿入位置、選択ノード数/総数、全経路長 (m)、未保存インジケータ＆保存ボタン、スナップトグル、マップ解像度、ズーム倍率、Fitボタンを表示すること。
- **未保存データ全経路保護規約 (Destructive Operation Guard)**:
  - ユーザーの作業データ保護を最優先とし、トップメニュー、キーボードショートカット（`Ctrl+N`, `Ctrl+O`）、ドラッグ＆ドロップ、ウェルカム画面の全経路において、未保存変更（`isDirty: true`）がある場合は必ず確認ダイアログを表示し、不意のデータ消失を完全に防止すること。
- **Undo / Redo 履歴管理**:
  - `Ctrl+Z` / `Ctrl+Y` によるノード追加・編集・削除の無制限な取り消し・やり直しをサポートすること。
  - 複数ノードの一括操作は単一の履歴スナップショット（`pushHistorySnapshot`）として原子的（Atomic）に記録すること。
- **グローバルショートカットの中央集約管理**:
  - `src/components/common/ShortcutManager.tsx` で一元管理し、ショートカットの変更時は必ずユーザー向け Help モーダル（`KeyboardShortcutsModal.tsx`）を同期更新すること（RULES.md 準拠）。
- **デザインシステム**:
  - デザイントークン（CSS変数）に基づく一貫したダークテーマ（Linear Style、高密度デスクトップUI）を適用し、Raw Tailwindカラーの直接指定を禁止すること。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1 パフォーマンス要件
- **大量ノード描画**: 数千個の Waypoint ノードおよび複雑なパスラインが存在する場合でも、PixiJS (WebGL) のバッチレンダリングにより 60 FPS の軽快なパン・ズーム・操作性を維持すること。
- **非同期処理とブロッキング防止**: 重い処理（Python プラグイン実行、大容量マップ合成、ファイル書き出し等）はバックグラウンドスレッドまたは非同期 IPC で実行し、UI メインスレッドのフリーズを防止すること。進捗表示には `LoadingOverlay` または `BackgroundLoadingBadge` を適切に使い分けること。

### 4.2 信頼性・データ整合性要件
- **型の厳格性**: ドメインコアおよび保存データには `StrictProjectData` 具象型を強制し、実行時型エラーや未定義参照を原理的に排除すること。
- **後方互換性保証**: 将来のバージョンアップ時も、旧バージョン（v0等）のプロジェクトファイルを損失なく読み込めるマイグレーションテストを自動テストスイートで保証すること。

### 4.3 移植性・動作環境要件
- Linux (WebKit2GTK) および Windows (WebView2) の両プラットフォームにおいて、フォント描画、レイアウト、ショートカットキー操作（Ctrl vs Meta等）が一貫して動作すること。

### 4.4 保守性・拡張性要件
- **疎結合設計**: コア描画エンジンは特定のプラグインや特定の ROS バージョンに依存せず、汎用的な幾何モデルとして動作すること。
- **新規プラグインの容易な追加**: マニフェストファイルとスクリプトを配置するだけで、本体コードの再コンパイルなしに即座にプラグインを認識・利用できること。

### 4.5 セキュリティ要件
- **Custom UI / 外部 HTML 隔離**: カスタム Web パネル（`CustomHtmlPanel`）で読み込まれる外部 HTML は、`iframe sandbox` 属性により適切なセキュリティ境界を設定し、許可された PostMessage API 経由でのみ本体アクションと通信させること。
- **ローカル IPC 通信の安全性**: Tauri コマンド呼び出しにおける引数バリデーション（パストラバーサル防止等）を Rust 側で徹底すること。

## 5. 配布・パッケージング要件 (Packaging & Distribution)

1. **単一実行バイナリ / AppImage**: 依存ライブラリを含まない環境でも即時起動可能なポータブル形式。
2. **ネイティブインストーラ (deb, msi)**: デスクトップエントリ、アプリアイコン、`.wptroj` ファイル拡張子関連付けを含むインストーラ。
3. **ZIP アーカイブ**: 組み込みプラグイン群（`python_sdk`）、サンプル設定（`custom-ui.sample.json`）、Handlebars テンプレート例を同梱した配布パッケージ。
4. **Docker 開発環境**: `Dockerfile.dev` および `compose.yaml` による統一開発環境。
