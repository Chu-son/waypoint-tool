# システム要件定義 (Requirements)

本ドキュメントは、ROS Waypoint Tool の主な要件、機能仕様、および開発ゴールを定義します。

## 1. 概要 (Overview)
ROS/ROS2 の Navigation パッケージと組み合わせて使用する、自律移動ロボット向け「Waypoint 作成ツール」のデスクトップアプリケーション。Tauri と React (PixiJS) を利用し、単一の実行バイナリとして配布可能。

## 2. 機能要件 (Functional Requirements)

### 2.1 マップ表示 (Map Visualization)
- ROS 標準の 2D Occupancy Grid Map ファイル（YAMLメタデータ + PGM/PNG画像）を読み込めること。
- 白（空き領域）、黒（障害物）、グレー（未知領域）のマップ上に、Waypoint や軌跡を描画できること。
- マウスドラッグによる「パン」と、マウスホイールによる「ズーム」操作が可能であること。
- 複数のマップをレイヤーとして管理し、不透明度や表示順序を変更できること。

### 2.2 Waypoint の作成・編集 (Waypoint Editing)
- キャンバス上をクリックすることで、任意の位置に Waypoint を作成できること。
- Waypoint には「位置（X, Y, Z）」と「姿勢（Yaw/Quaternion）」が含まれ、矢印マーカーで視覚化されること。
- マウスドラッグによる「移動」に加え、専用の「回転ハンドル」を用いることで、キャンバス上で直感的に姿勢（Yaw）を修正できること。
- インセプクターパネル（右ペイン）から、座標や角度を数値で直接編集できること。
- プロパティ描画機能により、キャンバス上のノード付近に `x, y, z, yaw, qx, qy, qz, qw` などの詳細な情報を表示できること。
- 複数選択（Shift+クリック等）による一括削除や一括編集をサポートすること。
- ヒエラルキーツリー（左ペイン）でのドラッグ＆ドロップによる順序の入れ替え。

### 2.3 カスタムプロパティ (Option Properties)
- Waypoint ごとに「目標速度」「停止時間」「動作モード」等の任意の属性を設定できること。
- 値の型として `string`, `float`, `integer`, `boolean`, `list` に対応し、Settings ダイアログから動的にスキーマを定義できること。
- 定義されたスキーマはプロジェクトファイル (`.wptroj`) 内に保存され、UI が自動的に入力フォームを生成すること。

### 2.4 自動生成機能とプラグイン (Generators & Plugin System)
- 手動のポイント追加に加え、スクリプトによる自動生成（ジェネレーター）をサポートすること。
- **Python / Rust (WASM) プラグイン**: 外部スクリプトをジェネレーターとして呼び出し可能。
- **インタラクション入力**: プラグインが必要とする入力（座標、矩形範囲等）をキャンバス上でユーザーが定義できること（`point`, `rectangle` 等のタイプに対応）。
- **インタラクションヒント**: プラグインがキャンバス上に補助図形を描画するためのヒントを定義でき、コアコードを修正せずに視覚的なフィードバックを可能にすること。
- **リアルタイムプレビュー**: パラメータ変更時に即座にキャンバス上のプレビューが更新されること。
- **プラグインアイコンのカスタマイズ**: 各プラグインに対して、プリセットのアイコン選択やユーザー独自の画像（PNG, JPG, SVG等）のアップロードを可能にし、ツールパネル上での識別性を向上させること。

### 2.5 入出力 (Data Export / Import)
- **プロジェクト保存**: 全ての状態（マップ画像、全ノード、スキーマ）を内包した `.wptroj` 形式の保存。
- **カスタムエクスポート**: Handlebars テンプレートを用いた自由なファイル出力。
- 定義したテンプレートごとにエクスポートされるファイル名のサフィックス（例: `_goal.yaml`）をカスタマイズできること。

### 2.6 UI/UX 操作性 (UI/UX Usability)
- **柔軟なパネルレイアウト**: 左右のサイドパネルを「タブ切り替え」もしくは「上下分割表示」に切り替えられること。これにより、複数の情報を同時に閲覧したい場合と、画面を広く使いたい場合の両方に対応すること。
- **インテリジェントなタブ切り替え**: キャンバス上で要素を選択した際やジェネレーターを起動した際に、自動的に関連するパネル（インスペクター等）へ切り替えること。
- **標準的なアプリケーションメニュー**: 上部メニュー（Top Menu）に File, Edit, View, Help の各項目を整理して配置し、設定、エクスポート、パネル開閉などの主要機能に一貫したアクセス手段を提供すること。
- **グローバルキーボードショートカット**: `Ctrl+S` (保存), `Ctrl+O` (開く), `Ctrl+A` (全選択), `Ctrl+E` (エクスポート) などの主要操作をショートカットで迅速に実行できること。また、`Help` メニューからこれらのショートカット一覧を確認できるヘルプ画面を提供すること。
- **高密度なアクセス性**:
    - **プラグインリスト**: 利用可能なジェネレーターをアイコンと説明付きで一覧表示し、サイドパネルから素早くアクセスできること。
    - **設定への直接遷移**: プラグインリストから直接、各プラグインの詳細設定画面へアクセスできること。
- **直感的なリセット操作**: `Esc` キーによる選択解除、ツールリセット、および基本パネル（レイヤー一覧等）への自動復帰をサポートすること。
- **ビュー設定の管理**:
    - **レイアウトのリセット**: パネルの開閉状態だけでなく、ユーザーが調整したパネル幅も含めて、ワンクリックで初期状態にリセットできること。
    - **情報の出し分け**: プロパティテキストやグリッドの表示/非表示を個別に切り替え、作業内容に応じてキャンバスの情報密度を最適化できること。
- **クイックアクセス機能**:
    - **マップフィット**: メニュー操作またはマウスホイール（中央ボタン）のダブルクリックにより、描画中のマップを即座にビューポートへ最適化（フィット）して表示すること。


## 3. 非機能要件 (Non-Functional Requirements)
- **クロスプラットフォーム**: Windows, Linux で動作すること。
- **パフォーマンス**: 数千個の Waypoint を配置しても操作が軽量であること（PixiJS の WebGL 描画活用）。
- **疎結合設計**: コアの描画ロジックが特定のプラグイン実装に依存しない汎用的な設計であること。
- **中央集約的なアクション・ショートカット管理**: キーボードショートカットやファイル操作ロジックを中央のマネージャーとグローバルストアに集約し、UIコンポーネントとロジックを分離することで、高い保守性を保つこと。
- **一貫したデザインシステム**: 独自の CSS 変数（Design Tokens）を用いたプレミアムなダークモードテーマを適用し、ボタン、入力フォーム、パネル等の全ての UI 要素において一貫した視覚的フィードバックと高品質な外観を提供すること。


## 4. 配布形式
1. **単一実行ファイル**: インストール不要なポータブル版。
2. **ZIP アーカイブ**: デフォルトプラグインや設定ファイルを同梱したもの。
3. **インストーラ形式**: OS への統合や拡張子の関連付けを想定。
