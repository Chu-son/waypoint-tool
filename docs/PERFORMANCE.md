# パフォーマンス設計ガイド (Performance)

本ドキュメントは、描画・状態更新・バックエンド処理の性能を保つための規約と、検討したが保留している改善候補をまとめたものです。
重い処理や頻繁に再描画される箇所（キャンバス、ツリー、エクスポート）を変更するときに読んでください。

性能改善では、**エクスポートされるファイルのバイト列、ブレンド結果のピクセル、プレビュー表示、ショートカットや選択の挙動を変えない**ことを前提にしています。出力や操作感が変わる改善は「保留中の改善候補」に記録し、個別に判断します。

---

## 1. 設計原則

### 1.1 バックエンド（Tauri コマンド）

- **重い処理はワーカースレッドで実行する**: エクスポート、地図・プロジェクトの読み込み、ブレンドなどは `async fn` にし、`run_blocking`（`spawn_blocking`）で実行する（`src-tauri/src/commands/mod.rs`）。同期コマンドはメインスレッドで動くため、実行中は WebView 全体が固まる。
- **ワーカーに移すのは、ブロッキングなローディングの中で呼ぶコマンドだけにする**: 画面が応答し続けると、処理中にユーザーが編集できてしまう。オーバーレイ（`runWithLoading({ blocking: true })`）で編集を止められない呼び出し元から使う短い処理（上書き保存の `save_project`、`read_image_base64`）は同期コマンドのままにし、メインスレッドが止まることで処理中の変更を防ぐ。例えば保存を非同期にすると、保存中の編集が保存済み扱い（`isDirty: false`）になる。目安として、数秒以内に終わる処理は同期のままにする。
- **ファイル系の処理は `IO_LOCK` で直列化する**: 同期コマンドだった頃は、メインスレッドで 1 本ずつ動くことで「同じファイルへの同時書き込み」「エクスポート中の読込」が起きなかった。この保証を `run_blocking_io` で維持する。読み取り専用で、エクスポート中も応答させたい処理（`check_export_conflicts`, `blend_map_preview`）だけを例外とする。
- **処理中の割り込みを UI 側で防ぐ**: 画面が応答し続けるため、blocking なローディングタスクの間は `ShortcutManager` が Escape を含むすべてのショートカットを無視する（処理を始めたモーダルを Escape で閉じさせない）（`docs/STATE_MACHINE.md` Axis 1）。
- **非同期の応答は古いものを捨てる**: 入力に応じて呼ぶコマンド（例: `useExportPlan` の競合チェック）は、effect の cleanup でフラグを立て、後から届いた古い応答で表示を上書きしない。
- **IPC で大きなデータを重複させない**: レイヤー画像、スクリーンショット、waypoint 一覧などはリクエストのトップレベルに 1 回だけ載せ、各アイテムは参照だけを持つ（`docs/ARCHITECTURE.md` のエクスポート節）。デコードもエクスポート 1 回につき 1 回にする。
- **ブレンドは走査範囲を絞る**: `blend_layers_to_image` は、レイヤーの 4 隅から求めた外接矩形の中だけを走査し、画像形式ごとの高速パスで画素を読む。変更するときは、テスト内の参照実装との完全一致テストを通すこと。

### 1.2 キャンバス（PixiJS / @pixi/react）

- **`draw` は安定した参照にする**: @pixi/react の `pixiGraphics` は、`draw` 関数の参照が変わったときだけ再描画する。`draw` は `useCallback` にし、描画の入力はすべて props と依存配列で渡す。`draw` の中で `useAppStore.getState()` や ref を読むと、その値が変わっても再描画されず表示が古くなる。
- **レイヤーは `React.memo` にし、項目ごとの描画は子コンポーネントに分ける**: 例えば `WaypointLayer` は 1 点ずつ `WaypointMarker` を描くので、1 点をドラッグしても他の点は再描画されない。子に渡す配列やオブジェクトは `useMemo` で安定させる。
- **キャンバスへのハンドラは `useStableCallback` で渡す**（`src/hooks/useStableCallback.ts`）: 参照が固定された関数から最新の処理を呼ぶため、ハンドラの中身が変わっても memo 化したレイヤーは再描画されない。描画に使う値をハンドラ経由で渡してはいけない（描画は props で受け取る）。
- **パンは React state にしない**: パン位置は `MapCanvas` の ref で持ち、ワールドコンテナの `x`/`y` を直接書き換える。JSX に `x`/`y` を書くと再描画で上書きされるので書かない。位置に追従する必要がある `GeoTileLayer` だけが `viewportStore`（`useSyncExternalStore`）を購読する。ズーム倍率は線幅やラベルに影響するため React state のままにする。
- **Pixi ツリーのコミットに合わせて処理する**: @pixi/react は `Application` の子を別の React root で、外側のコンポーネントより後からコミットする。Pixi オブジェクトの状態を揃える処理は、Pixi ツリー内に置いたコンポーネントの `useLayoutEffect`（`MapCanvas` の `AfterPixiCommit`）で行う。外側の effect で行うと、倍率と位置が 1 フレームずれることがある。
- **キャンバスの画像は描画直後に読む**: `preserveDrawingBuffer` は毎フレームのコストになるため使わない。画像が必要なときは `captureCanvasPng()`（`src/components/canvas/canvasCapture.ts`）で、`render()` の直後に同期で `toDataURL()` する。

### 1.3 React の状態と再描画

- **ストア全体を購読しない**: `useAppStore()` を引数なしで呼ぶと、どの状態が変わっても再描画される。必要な値だけをセレクタで購読するか、イベントハンドラの中で `useAppStore.getState()` を読む（例: `ShortcutManager`）。
- **選択判定は `Set` で行う**: 項目ごとに `selectedIds.includes(id)` を呼ぶと、項目数 × 選択数になる。`useMemo` で `Set` を作ってから判定する。
- **ツリーの親探索は索引を使う**: `findNodeParentId` は全ノードを走査する。同じツリーで繰り返し呼ぶ箇所では `buildParentIndex` の索引を渡す（`src/utils/treeUtils.ts`）。トップレベルの抽出は `collectTopLevelInOrder` / `excludeDescendantsOfOthers` を使う。
- **重い計算は入力が変わったときだけ行う**: 差分表示（`diffLines`, `diffValues`）やラベル配置などは `useMemo` にし、名前の入力やチェックの切り替えなど無関係な再描画で作り直さない。
- **閉じているモーダルの中身はマウントしない**: ただし、閉じても残すべき状態（例: エクスポートの前回選択項目、ファイル名の日時）は、常にマウントされている外側のコンポーネントに置く（`ExportModal`）。

## 2. 保留中の改善候補

期待できる効果はあるが、出力・見た目・操作感・開発環境のいずれかとのトレードオフがあるため保留している項目です。採用するときは、保留理由のトレードオフを受け入れるかを判断してください。

### 2.1 Docker 開発環境

| 内容 | 期待効果 | 保留理由 | 対象 |
|---|---|---|---|
| GPU パススルー（`/dev/dri` のマウント等） | WebGL がハードウェア描画になり、キャンバス全般が大幅に軽くなる | ホストの GPU・ドライバ構成に依存し、環境によっては起動しなくなる | `compose.yaml`, `Dockerfile.dev` |
| `LIBGL_ALWAYS_SOFTWARE` / `WEBKIT_DISABLE_COMPOSITING_MODE` の解除 | GPU 合成が使える環境では描画が軽くなる | 解除すると描画が崩れる・起動しない環境があるため設定されている | `Dockerfile.dev` |
| 透過ウィンドウの無効化 | ソフトウェア合成時の合成コストが減る | ウィンドウの見た目が変わる | `src-tauri/tauri.conf.json`（`transparent`） |
| 起動時の `npm install` の省略 | コンテナ起動が速くなる | 依存の更新が自動で反映されなくなる | `Dockerfile.dev`（`CMD`） |
| Cargo の dev プロファイルで依存を最適化（`opt-level`） | 開発ビルドでのブレンドや画像処理が速くなる | 初回ビルドが遅くなり、デバッグしにくくなる | `src-tauri/Cargo.toml` |

### 2.2 キャンバス描画

| 内容 | 期待効果 | 保留理由 | 対象 |
|---|---|---|---|
| ticker を止めて、変化があるときだけ描画する | 静止中の CPU/GPU 負荷がほぼなくなる | 描画漏れ（状態が変わったのに再描画されない）を全経路で防ぐ必要がある | `MapCanvas.tsx` |
| ズームも命令的に更新する | ズーム中の React 再描画がなくなる | 子レイヤーに倍率を渡さないと、ズーム中に線幅やラベルが一時的にずれる | `MapCanvas.tsx`, 各レイヤー |
| 線幅をスケールに依存させない（非スケール線） | ズームのたびの Graphics 再生成が減る | 線の見た目が変わる | 各レイヤー |
| ドラッグ中はラベル配置の再計算を止める | ドラッグが軽くなる | ドラッグ中にラベルが重なる | `WaypointLayer.tsx`（`computeLabelOffsets`） |
| ラベルの `dropShadow` をやめる | テキスト描画が軽くなる | ラベルの見た目が変わる | `MapCanvas.tsx` の `textStyle` |
| `AnnotationLayer` を項目ごとの子コンポーネントに分割 | 注釈 1 つのドラッグで全注釈が再描画されなくなる | 描画関数の大規模な書き換えが必要（現状は memo と `Set` のみ） | `AnnotationLayer.tsx` |
| フリーハンドの点を rAF ごとにまとめて反映 | pointermove ごとの再描画が減る | Pixi の描画コールバックの後に反映されるため、プレビューが 1 フレーム遅れる。pointermove はブラウザがフレーム単位にまとめることが多く、効果も小さい | `useMapEditFreehand.ts` |
| `Application` の `resizeTo` をキャンバスの親要素にする | パネル幅の変更でキャンバスのバッファが作り直されなくなる | エクスポートのスクリーンショットの画像サイズと内容が変わる | `MapCanvas.tsx` |
| ツリーの仮想化（表示範囲の行だけ描画） | 大量ノード時のツリー描画が軽くなる | スクロール位置の追従・ドラッグ&ドロップ・Reveal の挙動を作り直す必要がある | `WaypointTree.tsx`, `AnnotationTree.tsx` |

### 2.3 状態管理

| 内容 | 期待効果 | 保留理由 | 対象 |
|---|---|---|---|
| persist の書き込みを debounce | 頻繁な状態更新時の localStorage 書き込みが減る | 直後に終了すると最後の変更が保存されない | `src/stores/appStore.ts` |
| `cursorPosition` の更新を間引く | マウス移動ごとの購読者の再描画が減る | 座標表示の追従が遅れる | `mapSlice.ts`（`setCursorPosition`） |
| 履歴スナップショットで変更のない部分を参照共有する | Undo 履歴のメモリと複製コストが減る | 履歴の不変性の保証方法を変える必要がある | `historySlice.ts` |

### 2.4 エクスポートとブレンド

| 内容 | 期待効果 | 保留理由 | 対象 |
|---|---|---|---|
| テンプレート入力を debounce してプレビューを更新 | 入力中の再計算が減る | プレビューの追従が遅れる | `useExportPlan.ts` |
| プレビューの debounce と依存キーの厳密化 | 不要なブレンドの再実行が減る | `previewSyncKey` は画像の中身などを含まず、生配列の依存がそれを補っている。外すとプレビューが古いまま残る | `useBlendedPreview.ts` |
| プレビュー生成をブロッキングにしない | 生成中も編集できる | 生成中に編集できるようになる UX の変更 | `useBlendedPreview.ts` |
| ブレンドの rayon 並列化 | 大きな地図のブレンドが速くなる | 依存の追加。他コマンドと CPU を取り合う | `src-tauri/src/map/blending.rs` |
| レイヤーのデコード結果をキャッシュ | プレビューの再ブレンドが速くなる | メモリ使用量が増え、無効化の管理が必要 | `blend_preview.rs` |
| プレビュー解像度に上限を設ける | 巨大な地図でもプレビューが軽い | プレビューの精細さが下がる | `blend_preview.rs` |
| 非表示レイヤーを送らない | IPC が小さくなる | リージョンの可視判定（エントリなしは含める）を TS 側で正確に再現する必要がある。重複排除で効果の大半は得られている | `exportPackage.ts` |
| テンプレートエンジンの再利用、`BufWriter` | 書き出しが少し速くなる | 効果が小さいか未計測 | `export_pipeline.rs` |

### 2.5 その他

| 内容 | 期待効果 | 保留理由 | 対象 |
|---|---|---|---|
| 地図画像をバイナリ IPC / asset protocol で渡す | base64 の変換とサイズ増がなくなる | IPC と読み込み経路の作り直し | `src/api`, Tauri コマンド |
| 低負荷モード（エフェクトや装飾を省く） | 非力な環境での描画が軽くなる | 表示が変わる。設定項目の追加 | 描画全般 |
| インポート計画の分割計算 | 選択を変えたときの再計算が減る | `templateActions` などの選択が remap の内容に影響するため、分割すると結果が変わる恐れがある | `useProjectImport.ts` |
| 行差分を Myers 法にする | 大きなテキストの差分が速くなる | 最適な LCS が複数あるとき、差分行の並びが変わる | `src/utils/diff/lineDiff.ts` |

## 3. 調査中に見つかった要確認事項（性能以外）

性能改善の調査中に見つかった、挙動に関する確認事項です。直すと出力が変わるため、性能改善とは別に判断してください。

1. **マップ出力のファイル照合が前方一致**: `src/utils/exportPackage.ts` の `f.fileName.startsWith(region.name)`。リージョン名が別のリージョン名の前方一致（例: `area` と `area_2`）だと、別リージョンのファイルに誤ってマッチし得る。
2. **エクスポートのファイル名に使う日時がアプリ起動時刻に固定されている**: `ExportModal` の `sessionDate` は最初のマウント時に決まり、アプリを終了するまで変わらない。日時プレースホルダを含むファイル名やバックアップ名は、何度エクスポートしても同じ日時になる。意図した仕様か確認が必要。
3. **`ExportMapsModal` の `selectedRegions` が初期化後に更新されない**: `useState` の初期値でリージョン一覧から作るため、後から追加したリージョンは選択状態に含まれない。
4. **フリーハンドの最後の点が取りこぼされる可能性**: `useMapEditFreehand` の `handleFreehandDrawEnd` は、最後に描画された時点の `freehandPoints` を使う。pointermove の state 更新が描画される前に pointerup が届くと、その間の点が確定されない。
